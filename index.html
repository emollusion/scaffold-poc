What this PoC is for

Two questions only: does the Orient → Focus → Close loop hold up against real thumbs, and does local speech-to-text clear the latency bar for capture.

Validated here

  • The one-thing-at-a-time constraint under real screen size
  • Focus Engine v1 — the same pure score(task, energy, now) from §5, with the reason string it emits
  • Tap-to-mark splitting (1.1b) — whether it's actually low-friction
  • Desktop STT latency, if you wire the whisper adapter below

Not validated here

  • Mobile battery cost of on-device inference
  • Real background/offline behaviour
  • Flutter vs React Native packaging

Speech-to-text here

Pick a model in the capture sheet and press Load. Weights come from the Hugging Face CDN and are cached by the browser, so it's a one-time download per model. WebGPU is used when the browser offers it, plain WASM otherwise — the status line tells you which.

This is onnxruntime-web, not whisper.cpp. Same Whisper weights, different inference engine, and no cross-origin isolation required — which is the only reason this runs on GitHub Pages at all. Treat the timings as a comparison between model sizes and devices, not as a prediction of native mobile latency.

Swapping in real whisper.cpp later means replacing one function. Everything upstream reads window.ScaffoldSTT.transcribe(blob) and nothing else:

window.ScaffoldSTT = {
  name: 'whisper.cpp-wasm',
  local: true,
  transcribe: async (blob) => "text"
};

With no model loaded, the app runs the fallback path from §3.3 — audio is saved, the transcript is left blank and flagged needs review. Worth exercising deliberately; it's what a failed transcription looks like in production.
